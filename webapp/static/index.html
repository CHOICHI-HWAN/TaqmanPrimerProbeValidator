분석 파라미터 설정

config/config.yaml에 저장됩니다. mismatch 관련 값은 저장 후 "분석 다시하기"를 눌러야 기존 세트 결과에 반영됩니다(mfeprimer 재검색 없이 판정 기준만 다시 계산하므로 빠릅니다).

실행 도구

mfeprimer는 conda로 설치되지 않는 단독 실행 파일이라 직접 받아 경로를 지정해야 합니다 (setup.sh가 처음에 이 값을 묻고, 여기서 언제든 바꿀 수 있습니다). 저장하면 실제로 실행해 보고 mfeprimer가 맞을 때만 반영하며, 새 경로는 다음 분석부터 바로 쓰입니다.
mfeprimer의 --virus/degenerate 검색은 기본값이 4코어라서, 이 값을 머신의 실제 코어 수에 맞게 올려두면 "새 프라이머 세트 분석"과 파이프라인 재실행이 훨씬 빨라집니다 (인덱싱은 16, dimer는 2가 mfeprimer 자체 기본값이며 동일하게 이 값을 적용합니다; hairpin/probe 검색은 mfeprimer에 CPU 옵션이 없어 영향받지 않습니다).
⚠ 3' 말단 연속 매치 조건은 저장 후 "분석 다시하기"를 눌러야 반영됩니다 — probe mismatch/target coverage와 달리 mfeprimer 결과를 다시 계산해야 하는 값이라 reconcile만으로는 부족합니다.

새 프라이머 세트 분석

population DB(S 662개 / L 366개 게놈)에 대해 mismatch 0/1/2 primer 매치, probe 완전일치, 표준물질(KDCA) 매치, 참조유전체 결합위치, 게놈별 미스매치 표까지 한번에 계산합니다. degenerate base가 많은 프라이머는 mismatch=2 탐색에 몇 분 걸릴 수 있습니다.
